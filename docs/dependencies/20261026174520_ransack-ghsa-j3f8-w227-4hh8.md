# ransack GHSA-j3f8-w227-4hh8

## Dependency

- ransack (was 4.4.1, now 4.4.4)
- Constraint in this repo: none in the gemspec. Transitive via activeadmin 4.0.0.beta22 (ransack >= 4.0).
- Lockfiles: Gemfile.lock, gemfiles/rails72.gemfile.lock, gemfiles/rails8ruby34.gemfile.lock, gemfiles/rails8ruby4.gemfile.lock

## Symptom

bundler-audit matches ransack 4.4.1 against GHSA-j3f8-w227-4hh8. make release stops on gemfiles/rails72.gemfile while that pin remains.

## Evidence

- Advisory: one search key is parsed in time quadratic in its _-separated segment count, before allowlisting or strict mode rejects it. The same class of issue as GHSA-vxc9-rm8f-p56j, on the association-resolution path. Affected < 4.4.3, >= 5.0.0 and < 5.0.2, and < 6.0.0. Patched 4.4.3, 5.0.2, and 6.0.0. Published 2026-09-22. Severity on the advisory page: High. The page did not list a numeric CVSS score or a CVE ID.
- ActiveAdmin::ResourceController::DataAccess calls chain.ransack(params[:q] || {}, auth_object: active_admin_authorization) on index.
- Installed ransack 4.4.4 Context#key_within_depth_limit? treats a key with more underscores than Constants::MAX_KEY_DEPTH as unknown and names this advisory in the comment. Call sites in context.rb, adapters/active_record/context.rb, and nodes/grouping.rb return before the segment walk.

## Suggested fix

Upgrade lockfiles to ransack 4.4.4, which is past the 4.4.3 floor. Stay on the 4.4 line. Leave ransack off the gemspec. A single >= 4.4.3 floor would still allow vulnerable 5.0.0 and 5.0.1.

## Trigger

- bundler-audit scanner match during make release on 2026-10-26. ruby-advisory-db commit 04bbdaed29a22b4539f899ac1d6863ddaa326074, last updated 2026-10-26 09:56:27 -0400.

## Assessment target

- CI and test graphs: dummy ActiveAdmin index plus Gemfile.lock and gemfiles/*.gemfile.lock.
- Published gem payload: ransack is not a gemspec dependency. Host apps are not assessed here.

## Advisory

- GHSA-j3f8-w227-4hh8
- Severity on the advisory page: High
- The advisory page did not list a CVE ID when fetched on 2026-10-26, so a KEV lookup by CVE was not available from that page.

## Status

- CI and test graphs: fixed after lockfiles pin ransack 4.4.4. The installed gem contains the segment cap. bundler-audit check --update reported no vulnerabilities on Gemfile.lock and the three appraisal locks.
- Published gem payload: component not present. Host resolution stays on the host lockfile.

## Applicability

- Vulnerable component was present at 4.4.1.
- Exploit conditions are one long _-separated q key or sort value on an endpoint that calls ransack. The dummy index reaches that through ActiveAdmin. The advisory states that ransackable_attributes, strict mode, strong parameters, and Rack param_depth_limit do not stop the parse.

## Priority

- CI graph: high because bundler-audit fails make release, and the dummy index builds a Ransack search from request params.
- Published gem payload: the library file is not in this gem. Host exposure is outside this assessment.

## Disposition

- Upgrade. Same lock command as GHSA-vxc9-rm8f-p56j. Resolved 4.4.4, which covers both ransack advisories on the 4.4 line. Rejected 6.0.1 for this release.

## Next

- Keep the test graph on ransack 4.4 until a matrix run covers 6.x.
- A host that serves ActiveAdmin filters updates its own lock to ransack 4.4.3 or newer on the 4.4 line, 5.0.2 or newer on the 5.0 line, or 6.0.0 or newer. 4.4.2 fixes only the memory advisory.
